## 🎤 二、STAR 详讲版（面试口述脚本，约 90 秒）

> 这是在面试官说「介绍一下你这个项目」时的**口语化背稿**。不是念简历，是讲一个有起伏的产品故事。

### 🟢 S（Situation 情境）—— 讲痛点，建立共鸣

> 「我观察到求职准备这件事被切成了好几段：写简历用一个工具、看 JD 用招聘网站、准备面试又要到处搜面经、面完没人帮你复盘。AI 火起来之后，市面上出现一堆单点工具——有的只优化简历，有的只做模拟面试——但**没有一个把求职准备串成一个闭环**。候选人今天改完简历，明天面试挂了，也不知道是简历问题还是表达问题，更不知道下一步该补什么。」

### 🟡 T（Task 任务）—— 讲目标，聚焦可衡量

> 「所以我想做一个 AI 驱动的求职闭环平台，目标是让一个候选人从『拿到一个 JD』到『能自信走进面试间』，中间的所有环节——简历对标、缺口分析、模拟面试、弱项诊断、针对性练习——都能在**一个产品里自动流转、数据互通**。同时作为练手和验证 AI 产品化能力的产品，我要自己从 0 设计到上线。」

### 🟠 A（Action 行动）—— 讲你的产品决策（重头戏，分 3 块）

> **第一块是产品架构。** 我把求职准备拆成一条主线：**JD 分析 → 简历匹配 → 备面洞察 → AI 面试 → 弱项诊断 → 针对性优化 → 再次面试**，并且让数据双向流动——比如面试暴露的弱项，会反哺到下一轮简历优化和题库推荐。我用一个 6 维能力雷达和评分趋势来可视化这个过程。
>
> **第二块是 AI 能力的产品化，这是我最花心思的地方。** 我没有简单地在每个功能上『套一层大模型』，而是做了几个关键设计：
> - **Prompt 模板化**：把 7 个简历模块的优化逻辑抽象成 22 套结构化 Prompt，还设计了『标准 / 数据驱动 / 专家架构』三个版本，让同一个经历能适配不同岗位的包装风格。
> - **多模型适配**：用 OpenAI 兼容协议做了一层抽象，用户可以接入 12 家以上的模型厂商。这个决策的产品意义是——**把模型选择权和成本控制权交还给用户**，避免平台被某一家厂商的定价或可用性绑架。
> - **成本与延迟优化**：面试题库我用的是『分段并行生成题目 → 用户点了再生成解析 → 需要参考答案才懒加载』的三阶段策略。这样首屏快、token 花在刀刃上，符合求职用户『先看题、挑感兴趣的再深挖』的真实使用节奏。
>
> **第三块是 0-1 落地。** 我用 Vue3 + TypeScript 把整个产品从设计稿做到上线，包括多格式简历解析（PDF 还原了文本的换行结构、图片走浏览器端 OCR）、一个纯前端的无后端架构——数据默认存本地，可选 Supabase 云端同步且能优雅降级。最后用 Docker 和 Vercel 部署上线，现在是可以直接访问的真实产品。」

### 🔴 R（Result 结果）—— 讲产出，诚实但有亮点

> 「结果是这个产品已经**完整跑通并上线部署**，是一个可演示、可复盘的真实 AI 产品，不是 demo。对我个人而言，它验证了我能独立完成『AI 产品定义 → 能力设计 → 工程落地 → 上线』的完整闭环，这也是我今天来面 AI 产品经理最想证明的能力。」

> 💡 **讲完 R 之后主动抛钩子**：「您对里面哪块比较感兴趣？AI 闭环的设计，还是成本优化的思路？」——把话语权交回面试官，引导到你有准备的方向。

## 🧠 三、AI 能力产品化清单（一句话提炼，面试随时展开）

> 每个亮点背熟「**一句话价值 + 一个产品决策理由**」，面试官追问任意一个都能展开。

| 亮点 | 一句话价值 | 产品决策理由（被追问时说） |
|------|-----------|--------------------------|
| **22 套 Prompt 模板** | 把 AI 能力从「随机生成」变成「可控、可复用、可迭代」 | 模板化让效果可调优、让 A/B 测试成为可能，是 AI 产品稳定性的基础 |
| **三版本输出** | 一个经历适配多岗位的包装风格 | 求职用户最大的痛点之一是「一份简历投所有岗」，三版本解决了定制化成本 |
| **多模型适配（12+）** | 用户自主选择模型，降低厂商绑定与成本风险 | AI 产品最大的成本变量是 token，把选择权给用户是更可持续的商业模式 |
| **题库三阶段生成** | 首屏快 + token 省 + 体验顺 | 顺应「先浏览后深挖」的真实使用心智，避免一次性生成大量用户根本不看的内容 |
| **VRM 数字人 + 唇形同步** | 模拟面试从「文字聊天」升级为「有压力感的真实场景」 | 面试焦虑的本质是对「人」的反应，数字人能训练临场感，是产品差异点 |
| **本地优先 + 云端降级** | 隐私安全（简历不上传）+ 多端可用 | 简历是高敏感数据，本地优先建立信任；云端同步解决多设备，降级保证可用性 |
| **闭环学习系统** | 用数据把碎片功能串成「越用越准」的产品 | 单点工具留不住人，闭环 + 雷达图让用户看到进步，是留存的核心设计 |

## ⚠️ 四、数据化表达建议与避坑

### ✅ 可以放心写的硬数据（项目真实情况，可演示验证）

- 适配 **12+** 模型厂商（SiliconFlow / OpenRouter / DeepSeek / 智谱 / 百炼 / Moonshot / OpenAI / Ollama 等）
- **9 套**简历模板 + 自定义样式系统
- **7 大**简历编辑模块 + **22 套** Prompt 模板
- **6 维**能力雷达图
- 支持 **5 种**简历格式导入（PDF / Word / TXT / Markdown / 图片 OCR）
- VRM **5 元音口型** 唇形同步引擎

### ⛔ 绝对不要编的指标（一追问就破）

| 错误写法 | 为什么危险 | 正确替代 |
|---------|-----------|---------|
| 「用户量突破 10 万」 | 个人项目无推广，无法核实 | 不写，或如实说「已完成 MVP 上线，尚未规模化推广」 |
| 「匹配准确率提升 40%」 | 没有标注集和评测口径 | 「设计了基于 JD 关键词 + 语义的匹配评分，**下一步计划建立标注集做准确率评测**」 |
| 「留存率提升 XX%」 | 没有埋点和统计 | 「闭环设计的目标是提升留存，**已规划埋点指标，待推广后验证**」 |

### 🎯 推荐的「诚实但有含金量」表达句式

> - 「设计了 XX 的指标体系（北极星 / 漏斗），**下一步通过 A/B 验证**」 ← 体现你**懂增长方法论**，比硬编一个数字更专业。
> - 「上线后通过 XX 次自测 / 小范围试用，定位并修复了 XX 类问题」 ← 体现**迭代意识**。
> - 「该方案的理论收益是 token 成本下降 + 首屏延迟降低，**可在面试中现场演示对比**」 ← 把无法量化的收益变成**可演示的证据**。
