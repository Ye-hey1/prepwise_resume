## 🧩 一、PrepWise 产品架构讲解稿（作品集 / 面试现场讲项目）

> 适用场景：面试官说「详细讲讲你这个产品」「打开演示一下」时使用。建议**控制在 2-3 分钟**，先讲架构再演示。

### 1. 一句话定位

> 「PrepWise 是一个 AI 驱动的求职闭环平台，把『拿到 JD → 改简历 → 练面试 → 复盘』串成一条数据互通的完整链路。」

### 2. 产品架构（分层讲，文字版示意图）

```
┌─────────────────────────────────────────────────────────────┐
│  用户层    简历编辑 · JD 分析 · AI 面试 · 题库 · 闭环看板      │
├─────────────────────────────────────────────────────────────┤
│  AI 能力层  22套Prompt · 三版本优化 · JD匹配 · 题库三阶段      │
│             流式对话 · VRM数字人 · 智能排版                    │
├─────────────────────────────────────────────────────────────┤
│  模型适配层  OpenAI兼容协议 → 12+ 厂商（解耦 + 多模型路由）     │
├─────────────────────────────────────────────────────────────┤
│  数据层    localStorage + IndexedDB（本地优先）                │
│            Supabase（可选云端同步 + 降级）                      │
├─────────────────────────────────────────────────────────────┤
│  解析层    PDF(pdfjs) · Word(mammoth) · OCR(tesseract)        │
├─────────────────────────────────────────────────────────────┤
│  基础设施  Vue3 + TS + Pinia · Vite · Docker / Vercel          │
└─────────────────────────────────────────────────────────────┘
```

**讲法**：从上往下讲，重点突出**两层设计决策**：
- **AI 能力层**：所有 AI 功能共享同一套 Prompt 模板和容错机制（契约层），保证稳定可控；
- **模型适配层**：用 OpenAI 兼容协议做抽象，上层产品不感知具体厂商——这是「把模型选择权和成本权交还用户」的产品决策。

### 3. 核心数据流（讲闭环的关键）

> 「数据是这样流转的——用户贴一个 JD，系统先**解析 JD**（提取职责/技术栈/硬软要求）；然后和简历做**匹配评分 + 逐条证据核对**，告诉用户差在哪；接着基于缺口生成**备面洞察和题库**；用户进入 **AI 模拟面试**（可带 VRM 数字人）；面试结束后，表现数据**回流**到 6 维能力雷达图，并推荐**下一步针对性优化**。整个流程的数据是**双向流动**的——面试暴露的弱项，会反哺简历优化和题库推荐。这就是『越用越懂用户』的闭环。」

### 4. 三个最值得讲的设计决策（被追问时展开）

| 决策 | 产品理由 |
|------|---------|
| **多模型适配** | 供应商风险对冲 + 用户自主控成本 + 商业模式可持续 |
| **题库三阶段生成** | 匹配用户「先浏览后深挖」心智 + 把昂贵 token 推迟到确认需要后 |
| **本地优先架构** | 简历高敏感 → 隐私建立信任 + 零服务器成本 + 离线可用 |

### 5. 现场演示动线（Demo Script，90 秒走完）

> 1. **粘贴一个真实 JD** → 展示 JD 解析 + 匹配评分 + 缺口（**核心价值，先给冲击**）；
> 2. **点开一道生成的面试题** → 展示按需生成的解析（**讲成本优化的现场证据**）；
> 3. **进入 AI 面试** → 开 VRM 数字人，展示流式对话 + 唇形同步（**体验差异化**）；
> 4. **回到闭环看板** → 展示雷达图 + 评分趋势（**讲闭环留存**）。

> 💡 演示前**预先填好一份简历和 JD**，别现场输入浪费时间；网络/AI 配置提前测好。

## 🔧 二、AI PM 必备技术理解力话术速查

> 用途：被面试官（尤其技术背景的）追问技术时，用「**PM 能听懂、又能体现你懂原理**」的方式回答。每条 = 一句话本质 + 在 PrepWise 的体现。

| 技术 | PM 视角一句话本质 | 在 PrepWise 的体现 |
|------|------------------|-------------------|
| **LLM 大模型** | 基于上文预测下一个 token 的概率引擎，会幻觉、对表述敏感、有上下文上限 | 所有 AI 功能的底座；产品要做容错和可验证 |
| **Prompt 工程** | 用结构化措辞约束 AI 输出，把不可控变可控 | 22 套模板 + 三版本规则，让输出可解析可入库 |
| **Token** | 模型处理的最小单位，按量计费 = 成本 | 题库三阶段省 token 的根本原因 |
| **SSE 流式** | 服务端把结果一段段推送，消除 AI 延迟的体感损耗 | 所有 AI 输出打字机式渲染 + 可中断 |
| **OpenAI 兼容协议** | 用统一接口适配多厂商，屏蔽差异 | 12+ 模型适配的技术基础 |
| **JSON 清洗/容错** | 永不假设 AI 返回规范数据，产品要能优雅退化 | cleanJsonResponse + normalize + 降级 |
| **OCR（tesseract）** | 在浏览器端识别图片文字，本地完成保隐私 | 图片简历解析 + PDF 无文本层时降级 |
| **PDF 文本结构还原** | 用文本坐标（Y 值变化）推断换行，还原排版 | PDF 简历解析保留段落结构 |
| **VRM / Three.js** | 浏览器内渲染 3D 虚拟形象，提升沉浸感 | AI 面试的数字人面试官 |
| **唇形同步** | 文字→音素→口型帧序列，驱动嘴部动画 | 自研汉字→5 元音口型映射引擎 |
| **本地优先存储** | 数据默认存浏览器（localStorage/IndexedDB），不传服务器 | 简历隐私保护 + 零后端成本 |
| **Supabase + 降级** | 可选云端同步，不可用时自动回退本地 | 多端同步 + 保证可用性 |
| **XSS 防护（DOMPurify）** | 过滤用户/AI 输入的恶意脚本，防注入 | 富文本内容安全 |
| **Pinia 状态管理** | 集中管理前端状态，数据流清晰可追踪 | 简历数据、AI 配置、面试状态统一管理 |

> 🎯 **答题心法**：被问技术细节时，**永远把回答拉回产品意义**。例如问「Pinia 怎么用的」→ 答「我用 Pinia 集中管理简历和面试状态，**这样闭环里各环节数据能实时同步、用户切换模块不丢上下文**」——讲产品价值，不讲 API。

## 🙋 四、面试结尾反问清单（体现 PM 思维）

> 面试官问「你有什么想问我的？」时，**千万别说没有**。好反问 = 加分项，体现你的业务 sense 和 AI 理解。**选 2-3 个最契合岗位的问**。

### 🏢 关于业务与产品（体现你关心价值）

1. 「贵司的 AI 产品目前最大的瓶颈，是在**模型能力、成本、还是用户接受度**？」
2. 「团队怎么衡量一个 AI 功能的成功？**效果指标（如准确率）和业务指标（如留存/转化）**之间怎么平衡？」
3. 「你们的 AI 产品，用户对**成本和隐私**的接受度如何？是 Freemium 还是其他模式？」

### 🤝 关于团队与协作（体现你想清楚怎么融入）

4. 「AI 产品经理在团队里，和**算法、工程、设计**的协作边界是怎样的？需求到上线一般怎么流转？」
5. 「团队里 AI PM 更偏**产品定义**还是**模型效果调优**？日常工作的重心是什么？」

### 📈 关于挑战与期待（体现你有判断力）

6. 「您觉得做这个岗位，**最关键的能力**是什么？我如果加入，前三个月最该补齐什么？」
7. 「贵司在 AI 产品上，未来一年**最想突破的方向**是什么？」

### 🌱 关于成长（体现长期主义，留好印象）

8. 「您本人在 AI 产品这条路上，**最大的经验教训**是什么？」（面试官喜欢聊自己的经验，拉近距离）

> ⚠️ **反问避坑**：
> - 别问「**薪资/加班/福利**」（HR 环节再问，技术/业务面问显得格局小）；
> - 别问官网上能查到的基本信息；
> - 别一个都不问 —— 会被判定为「对这个岗位没兴趣 / 没思考」。
